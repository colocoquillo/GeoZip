# GeoZip format GZ1 (draft)

A GeoZip archive is a **standard ZIP** encrypted with WinZip AES-256 (AE-2).
The AES password is not typed by the user. It is derived with Argon2id from an
ordered list of **places** (300 m cells) and, depending on the level, **words**
from a fixed list.

This document is normative. An implementation conforms if it produces the same
results as the test vectors in `crates/geozip-core`.

> **Status: draft.** The format, and the word list in particular, may change
> until version 1.0.

## 1. Parameters

| Parameter | Value |
|---|---|
| Identifier | `GZ1` |
| Container | ZIP (APPNOTE 6.3), ZIP64 when needed |
| Per-entry encryption | WinZip AES-256, AE-2 (AES-CTR + HMAC-SHA1) |
| Compression | Deflate or stored |
| Key derivation | Argon2id v1.3, 32-byte output |
| Salt | 16 random bytes per archive |
| Grid | 300 m, with an optional 150 m shift per axis |
| Word list | version 1: 1850 concepts (`wordlist/gz1-concepts.tsv`) |

### Levels

| Level | Places | Words per place | Argon2id (memory, passes, lanes) |
|---|---|---|---|
| High | 5 | 0 | 256 MiB, 3, 4 |
| Extreme | 5 | 1 | 512 MiB, 4, 4 |
| Extreme, two words | 5 | 2 | 512 MiB, 4, 4 |

The level is not stored as such. The header carries the number of places, the
words per place and the Argon2id parameters, and those are what a reader uses.
A reader accepts 1 to 16 places and 0 to 4 words per place.

## 2. Grid

Input: WGS84 latitude and longitude in decimal degrees, `lat ∈ [-90, 90]`,
`lon ∈ [-180, 180]`. A longitude of `180` is treated as `-180`.

Constants:

```
G = 300          metres per cell
H = 150          metres of shift
M = 111320       metres per degree of latitude
R = 0.017453292519943295   radians per degree
```

Each place has a public **shift** `(sLat, sLon)`, each 0 or 1. For a point
`(lat, lon)`:

```
latCell = floor((lat × M − sLat × H) / G)
latC    = clamp(((latCell + 0.5) × G + sLat × H) / M, −90, 90)
k       = M × cos(latC × R)
lonCell = floor((lon × k − sLon × H) / G)
```

All operations are IEEE 754 binary64. The cosine must come from a correctly
rounded implementation or, as in the reference code, from `libm`, so that the
result does not depend on the platform.

The longitude scale `k` uses the latitude of the **centre of the row of
cells**, not of the point. Every point in a row then shares the same scale and
cells are 300 × 300 m rectangles anywhere in the world.

### Choosing the shift when creating

For each place, and separately for each axis, the writer chooses the shift that
leaves the point farther from the edge of its cell (0 on a tie). Latitude is
decided first; longitude is decided with that latitude fixed. This guarantees
the chosen point is **75 m or more** from every edge, so at least 75 m of error
in any direction is tolerated when opening.

The shift is stored in the clear. It reveals at most 2 bits per place.

## 3. Word list

`wordlist/gz1-concepts.tsv` has 1850 rows `id, en, es, en_alias, es_alias`. The
secret is the **id** (0–1849), not the text: "trompeta" and "trumpet" are the
same id.

To look up a word typed by the user it is normalised: lower case, NFD
decomposition, combining marks removed (`á→a`, `ü→u`, `ñ→n`). Within one
language no normalised form, word or alias, appears twice. If the same form
appears in two languages, it is the same id.

The words for a place are generated by the program from the operating system's
random source and are distinct from each other. No row changes id or is removed
in later versions; only languages and aliases may be added.

## 4. Key derivation

### Canonical string

ASCII text, with a `\n` at the end of every line:

```
GZ1
places=<n>;words=<w>;wordlist=<v>
<latCell>,<lonCell>,<sLat><sLon>[:<id>,<id>…]      (one line per place, in order)
```

- Integers are decimal, with a leading `-` when negative and no leading zeros.
- The words of a place are listed in ascending id order (their order is not
  part of the secret). With no words, the line ends after the shift.

Example (2 places, 2 words each, no shift):

```
GZ1
places=2;words=2;wordlist=1
14842,-853,00:5,900
15213,-561,00:7,1849
```

### Key

```
key      = Argon2id(password = canonical, salt = salt, m, t, p, 32 bytes)
password = base64url_no_padding(key)          (43 ASCII characters)
```

`password` is the AES password of every encrypted entry in the ZIP. From there
WinZip AE-2 applies unchanged (PBKDF2-HMAC-SHA1 with its own per-entry salt).
Any tool that supports AES ZIP opens the archive when given that password.

## 5. Header

One ASCII line of `key=value` pairs separated by spaces:

```
GZ1 places=5 words=1 wordlist=1 m=524288 t=4 p=4 salt=<22 chars> shifts=01.10.11.00.10 names=hidden
```

| Field | Meaning |
|---|---|
| `places` | number of places |
| `words` | words per place |
| `wordlist` | word list version |
| `m`, `t`, `p` | Argon2id: memory in KiB, passes, lanes |
| `salt` | 16 bytes in base64url without padding |
| `shifts` | one `sLat sLon` pair per place, separated by `.` |
| `names` | `visible` or `hidden` |

Every field is required, none may repeat, and unknown fields are rejected.
`places` must equal the number of pairs in `shifts`.

It is stored in two places:

1. The **ZIP comment** (first line).
2. An **extra field** with id `0x5A47` ("GZ") on every encrypted entry, as a
   copy in case a tool removes the comment.

A reader rejects `m > 4 GiB`, `t > 64` or `p > 64`, so that a tampered header
cannot exhaust the machine.

The header is not authenticated separately. Changing any field changes the
derived key: the salt and parameters feed Argon2id; places, words, list version
and shifts feed the canonical string.

## 6. Contents

### Visible names (`names=visible`)

Each file is an entry encrypted with AE-2. Directories are unencrypted entries
with no data. Names, sizes and dates are visible.

When opening, a reader **rejects the archive** if it finds an entry that is
neither a directory nor encrypted. ZIP does not authenticate the archive as a
whole, and this stops a third party from adding unencrypted files that would be
extracted next to the real ones.

### Hidden names (`names=hidden`)

The outer ZIP has a single entry, `contenido.zip`, stored without compression
and encrypted with AE-2. Its content is an ordinary unencrypted ZIP holding the
real files. From outside only the total size is visible.

### Metadata

The modification time is kept (DOS field in UTC plus the extended timestamp
`0x5455`), as are Unix permissions (`rwx`). Symbolic links are not included.

## 7. What the format does not do

- **It does not authenticate the archive as a whole.** Each entry has its own
  HMAC, but someone with write access can delete, reorder or rename entries
  (AE-2 does not authenticate names). With hidden names this does not apply:
  everything is inside one authenticated entry.
- **It does not hide** the size of the contents or, with visible names, the
  folder structure.
- **There is no recovery.** Without the places, their order and the words, the
  contents cannot be decrypted.
